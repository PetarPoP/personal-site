# Petar Popović — portfolio

Personal CV / portfolio site built with [TanStack Start](https://tanstack.com/start) and Tailwind CSS v4.
It is one scrolling page: a hero whose dithered teal "water" grows to fill the screen as you scroll, then Work
(the CV's key projects, filterable), Experience, what Petar is listening to on Spotify, and Contact, with dithered
bands blending each section into the next. Wheel scrolling is smoothed with [Lenis](https://github.com/darkroomengineering/lenis)
and the scrollbar is hidden. It works the same on phones; the dither uses bigger pixels there.

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # static page + Worker, in dist/
npm run preview  # the build, running in Cloudflare's runtime locally
npm run deploy   # build and `wrangler deploy`
```

## Deploying (Cloudflare Workers)

The site runs on Cloudflare Workers with static assets (`wrangler.jsonc`, `@cloudflare/vite-plugin`). The page is
prerendered to `index.html` at build time, and so are `sitemap.xml` and `robots.txt`. Cloudflare serves those files
without running the Worker, which keeps them free and unlimited. The Worker only runs for the server functions
(Spotify, and the photo list) and `/api/photos/<id>`. The Spotify section asks only while it is on screen, every 30
seconds, and the answer is shared by all visitors for 15 seconds.

With the repo connected in Cloudflare → Workers & Pages (Workers Builds):

- Build command: `npm run build`, deploy command: `npx wrangler deploy`.
- Secrets go in the Worker's Settings → Variables and Secrets (or `npx wrangler secret put NAME`), never in the repo:
  `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`, `SPOTIFY_REFRESH_TOKEN`, `GITHUB_TOKEN`, `IMMICH_SHARE_URL`. PR previews
  (`wrangler preview`) don't get them; add them with `npx wrangler preview base-config secret put NAME` if wanted.
- Storage is the Cloudflare D1 database `personal-site`, bound as `DB` (previews use `personal-site-preview`). It only
  keeps the newest Spotify refresh token (table `kv`, created on first use).
- Domains: add `petarpopovic.com` (and `www`) under the Worker's Settings → Domains & Routes → Custom domain. For
  `petarpop.com`, add the domain to Cloudflare and create a Redirect Rule sending every request to
  `https://petarpopovic.com` with the same path, status 301. `src/lib/seo.ts` has the canonical address used in links,
  the sitemap and link previews.

## SEO

The root route sets the title, description, canonical link, Open Graph and Twitter tags with `public/og.png`
(1200×630, a screenshot of the hero) and schema.org data for Google and AI search: the website, a `ProfilePage`, the
`Person` and the projects (`src/lib/seo.ts`). The sitemap is generated by TanStack Start from the `pages` list in
`vite.config.ts`. `/llms.txt` and `/llms-full.txt` are the whole page as Markdown for AI assistants
(`src/lib/llms.ts`, built from `portfolio.ts`, prerendered like the page).

To rank for the name: the title, the main heading (the name is in it for screen readers and search engines) and the
schema.org `Person` (with "Petar Popovic" as an alternate spelling) all lead with "Petar Popović". Outside the code:
verify `petarpopovic.com` in Google Search Console (DNS record in Cloudflare), submit `/sitemap.xml` there, and link to
the site from every profile (GitHub, LinkedIn, Instagram…); add those profile URLs to `sameAs` in `src/lib/seo.ts`. The old POP/OS addresses (`/projects`, `/photos`, `/cv`, …)
redirect to the matching section via `public/_redirects`.

## Where things live

- `src/data/portfolio.ts` — all copy: profile, projects, experience and education.
- `src/components/Site.tsx` — the page and its scroll effects; `src/components/Spotify.tsx` — the now-playing player
  (cover dithered into the teal palette); `src/components/Photos.tsx` — the photo grid and viewer (not on the page
  right now).
- `src/lib/github.ts` — server function that lists the public GitHub repos with `GITHUB_TOKEN` (no scopes needed);
  a project card links to its `repo` (set in `portfolio.ts`) only while that repo is public.
- `src/lib/spotify.ts` — server function that asks Spotify; `src/lib/db.ts` — the D1 key/value table.
- `src/lib/dither.ts` — the ordered-dither drawing for the hero and the bands.
- `public/petar-popovic-cv-en.pdf`, `public/petar-popovic-cv-hr.pdf` — the CVs linked from Contact.
- `src/styles.css` — palette (`@theme` tokens) and utilities.

## Spotify

The player shows the song playing right now, or the last one played, and hides itself when Spotify isn't set up or
fails. Set the three `SPOTIFY_*` secrets above. To make a refresh token (scopes `user-read-currently-playing` and
`user-read-recently-played`), add `http://127.0.0.1:3000/callback` as a Redirect URI of the Spotify app, run
`SPOTIFY_CLIENT_ID=… SPOTIFY_CLIENT_SECRET=… npm run spotify-token`, open the printed link and approve. When Spotify
hands out a newer refresh token, the site keeps it in D1. Locally, `SPOTIFY_MOCK=1` in `.dev.vars` shows a fixed
song in `npm run dev` (`SPOTIFY_MOCK=recent` shows it as last played; `SPOTIFY_MOCK_IMAGE=<url>` adds a cover).

## Photos (Immich, currently not on the page)

The Photos section (put `<Photos />` back in `Site.tsx` to show it) shows one album from Petar's own Immich server, read through the album's public share link. Add as a
Worker secret:

- `IMMICH_SHARE_URL` — the album's share link, e.g. `https://photos.example.com/share/<key>` (a `/s/<slug>` link works too)

The server reads the album (at most every 5 minutes) and every image goes through `/api/photos/<id>`, so visitors never
see the server's address or the share key, and the photos are never copied anywhere. The grid uses Immich's small
thumbnails and the viewer shows the thumbnail at once while the larger preview loads. Browsers cache each photo for a
week, and the Worker keeps a copy in Cloudflare's cache for a month. Captions come from the photo's description in
Immich, else its city. Without `IMMICH_SHARE_URL` (or when the server can't be reached) the section is hidden.

Note: in `npm run dev`, Vite answers image requests to `/api/photos/…` itself, so the photos only load in a build
(`npm run build && npm run preview`). For local testing put `IMMICH_SHARE_URL=…` in `.dev.vars` before building.
